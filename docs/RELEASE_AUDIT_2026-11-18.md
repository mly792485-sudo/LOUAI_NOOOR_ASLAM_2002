# تقرير تدقيق تحديث نور الإسلام — 18 نوفمبر 2026

## ما تم تنفيذه

- تحسين مفتاح تخزين مواقيت الصلاة ليشمل المنطقة الزمنية، الدولة، المدينة، الإحداثيات، طريقة الحساب، المذهب، والتاريخ.
- إظهار المنطقة الزمنية التي يعيدها مصدر المواقيت عند توفرها، واستخدامها في عرض التاريخ الميلادي.
- إبقاء اختيار الموقع اليدوي متاحًا عند رفض صلاحية GPS.
- إبقاء المواقيت اليومية والأسبوعية مرتبطة بالتاريخ والموقع وطريقة الحساب بدل جدول ثابت.
- جدولة نافذة ثلاثة أيام من إشعارات الصلاة حتى لا تتجاوز قيود الإشعارات المعلقة في iOS.
- الحفاظ على ثلاث مراحل للصلاة: تنبيه صامت قبل الأذان، إشعار الأذان، ثم إشعار الإقامة.
- إعطاء أولوية لإشعارات `pre_adhan` و`adhan` و`iqama` قبل تذكيرات الأذكار عند وجود حد للنظام.
- إزالة نسخ أصوات إشعارات النظام المكررة من حزمة الويب مع إبقاء ملفاتها الأصلية داخل iOS وAndroid.
- استمرار حماية خادم المستشار: حد الطلبات، حجم السؤال، CORS، وإلغاء الطلب عند انقطاع العميل.
- استمرار التحذير الثابت في المستشار بأنه أداة بحث وليس مفتيًا.
- استمرار منع النصوص الدينية المولدة آليًا داخل سياسة المحتوى.

## الاختبارات المنفذة

- `tsc --noEmit`: ناجح.
- `npm run build`: ناجح.
- فحص ملفات الصوت الأصلية في Android وiOS: ناجح.
- سيتم تشغيل `npx cap sync` قبل التسليم النهائي.
- بناء Android المحلي يحتاج JDK كاملًا يحتوي `javac`؛ بيئة Sandbox الحالية فشلت بسبب Java toolchain غير مكتمل، لذلك يعتمد بناء APK/AAB على GitHub Actions.
- بناء iOS يحتاج macOS/Xcode؛ سيتم تشغيله عبر GitHub Actions وإنشاء IPA غير موقّع إذا نجح الـ workflow.

## حدود يجب عدم إخفائها

- دقة المواقيت العالمية تعتمد على طريقة الحساب ومصدر الدولة المحلي. لا يوجد جدول واحد رسمي عالمي لكل الدول.
- المناطق ذات خطوط العرض العالية قد تحتاج إعدادات معالجة خاصة واختبارًا محليًا.
- IPA غير الموقّع لا يثبت مباشرة على iPhone قبل توقيعه بشهادة Apple وProvisioning Profile.
- تشغيل أذان كامل من إشعار iOS وحده مقيد بسياسات النظام؛ صوت الإشعار ليس بديلًا عن تشغيل الخلفية الأصلي.
- لا تُعتبر Firebase مفعلة فعليًا في الإصدار المنشور إلا بعد إضافة قيم Secrets وتفعيل Email/Password في Firebase Console.
