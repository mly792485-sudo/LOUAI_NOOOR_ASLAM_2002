# مشروع تطوير نور الإسلام

هذا الملف يحول المواصفات المرفقة إلى خطة تنفيذ قابلة للاختبار. الهدف هو تطوير نور الإسلام بهوية مستقلة مستوحاة من احتياجات المسلم اليومية، من دون نسخ شعار أو ملفات أو كود تطبيق آخر.

## الحالة الحالية

### منفذ وموجود في المشروع

- مواقيت ديناميكية حسب المدينة والإحداثيات والتاريخ، مع طرق حساب متعددة والمذهب الحنفي/القياسي.
- تحديث عند تغير الموقع أو المدينة، وجدول أسبوعي، والإمساك والإفطار والثلث الأخير عند توفرها من المصدر.
- إعدادات تعديل الدقائق واختيار الموقع يدويًا.
- القرآن والمصحف الصفحي، الحفظ المرجعي، البحث، المفضلة، والتفسير المتصل بمصدر البيانات الموجود.
- الأذكار والتسبيح والختمة والقبلة والرقية والأحاديث والمكتبة والمستشار.
- إذاعة مباشرة مع اكتشاف محطات حسب الدولة ومحاولة رابط احتياطي.
- إشعارات الأذان والإقامة والأذكار المجدولة، مع أولوية أزواج الأذان/الإقامة ضمن حد الإشعارات في النظام.
- مركز العبادات اليومي مع حفظ التقدم محليًا.
- التقويم الهجري والميلادي والمناسبات العامة مع تنبيه اختلاف إعلان الرؤية.
- بناء iOS وAndroid عبر GitHub Actions ورفع IPA/APK/AAB إلى Releases.

## المرحلة التالية ذات الأولوية

1. **المواقيت**: إضافة عرض شهري/إمساكية رمضان، حفظ المدن المفضلة، وتحسين آلية اختيار مصدر محلي عند توفره بدل اعتبار أي API اعتمادًا حكوميًا.
2. **التنبيهات**: اختبار كل قناة وصوت على أجهزة حقيقية، وإضافة إعداد مستقل لكل صلاة عندما تكون واجهة النظام قادرة على حفظه.
3. **الإذاعة**: اختبار الروابط الفعلية، التبديل التلقائي عند الانقطاع، وتحسين Media Session. استمرار التشغيل خلف الشاشة يحتاج تكاملًا أصليًا ومصدر بث يدعم ذلك.
4. **القرآن والختمة**: إضافة إدارة خطط متعددة وإحصائيات، ثم تنزيل المحتوى المرخص فقط للعمل دون إنترنت.
5. **الأذكار والأدعية**: مراجعة كل نص ومرجع وعدد تكرار قبل إضافة أي محتوى جديد.
6. **القبلة**: تحسين رسالة المعايرة ودقة البوصلة، ثم إضافة الخريطة أو AR فقط بعد توفير إذن ومكوّن أصلي مناسب.
7. **رمضان والطاعات**: توسيع مركز العبادات بإحصائيات أسبوعية وشهرية وتذكيرات قابلة للتخصيص.
8. **الويدجت**: إنشاء Widget Extension مستقلة لـ iOS وApp Widget لـ Android؛ لا يمكن تنفيذها من React داخل WebView وحده.
9. **المزامنة والتحديث عن بعد**: إضافة Backend وقاعدة بيانات وقواعد صلاحيات ونسخ احتياطي قبل مزامنة بيانات المستخدم.

## قيود يجب عدم إخفائها

- تشغيل أذان كامل عند إغلاق التطبيق يعتمد على قيود iOS وAndroid وطريقة توقيع التطبيق وقناة الصوت؛ الإشعار الصوتي ليس مشغلًا صوتيًا طويلًا مضمونًا.
- IPA غير الموقّع لا يثبت على iPhone. يلزم Apple Distribution Certificate وProvisioning Profile أو TestFlight.
- ويدجت iOS وLive Activities تتطلب كودًا أصليًا في Xcode وتوقيع Apple.
- المحطات الخارجية قد تتوقف أو تغير الرابط؛ لا يمكن ضمان بث طرف ثالث من داخل التطبيق دون مصدر يضمن الاستقرار والترخيص.
- إعلان رمضان والعيدين يتبع جهة الرؤية الرسمية في كل دولة، ولا ينبغي للتطبيق أن يقدمه كتاريخ قطعي من الحساب وحده.
- أي محتوى شرعي جديد يجب أن يحمل مصدرًا واضحًا، ولا يجوز توليد آيات أو فتاوى بواسطة الذكاء الاصطناعي.

## معيار قبول كل مرحلة

- `npm run lint` ينجح.
- `npm run build` ينجح.
- `git diff --check` ينجح.
- اختبار يدوي للواجهة على الهاتف.
- اختبار مواقيت في البحرين ومصر والسعودية ومدينة أخرى على الأقل.
- توثيق المصدر أو القيد بجانب الميزة، وعدم اعتبار نجاح البناء دليلًا على نجاح اختبار جهاز حقيقي.
