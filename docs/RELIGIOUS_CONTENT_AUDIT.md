# مراجعة المحتوى الشرعي في نور الإسلام

## سياسة أساسية

لا يُستخدم الذكاء الاصطناعي كمصدر للآيات أو الأحاديث أو الأذكار أو الأدعية أو الرقية أو الفتاوى. الذكاء الاصطناعي يمكنه تنظيم نتائج موثقة أو شرحها مع التصريح بالمصدر، لكنه لا ينشئ نصًا شرعيًا جديدًا ولا ينسب قولًا إلى النبي ﷺ أو العلماء دون مرجع قابل للتحقق.

## الحالة الحالية

- نسخة React تحتوي على بيانات أذكار وأحاديث وحقول مصدر في عدد من العناصر، لكنها تحتاج مراجعة بشرية منهجية للتأكد من النص والرقم ودرجة الحديث وعدم التكرار.
- نسخة Flutter تحتوي ملفات بيانات بصيغة TypeScript داخل `assets/data/`، وهذه الملفات ليست مصدرًا قابلًا للاستهلاك مباشرة في Dart؛ يجب تحويلها إلى JSON/Dart models موثقة قبل اعتمادها في Flutter.
- مسار التفسير الخلفي الذي كان يطلب من النموذج توليد تفسير تم تعطيله في هذا التحديث؛ لن يُعاد تفعيله حتى تُضاف قاعدة تفسير موثقة ومراجعة.
- المستشار الإسلامي ما زال أداة بحث ومساعدة، وليس مفتيًا، ويجب أن يصرح بعدم التحقق عند غياب مصدر.

## نموذج المصدر المطلوب لكل عنصر

كل عنصر ديني جديد يجب أن يحتوي على:

- `id` ثابت.
- `category`.
- `text` بالنص المعتمد دون إعادة صياغة.
- `sourceType`: قرآن، حديث، أثر، دعاء عام، أو مادة تعليمية.
- `sourceBook`.
- `sourceReference`: رقم الحديث أو السورة والآية عند توفره.
- `grade` للأحاديث عند توفر حكم محدث موثوق.
- `sourceUrl` للرابط القابل للمراجعة.
- `reviewStatus`: `verified`, `needs_review`, أو `rejected`.
- `audioUrl` فقط إذا كان التسجيل مطابقًا للنص ومسموح الاستخدام.

لا يظهر للمستخدم عنصر حالته `needs_review` أو `rejected` كمحتوى موثوق.

## مراحل التنفيذ

1. استخراج كل عناصر الأذكار والأحاديث والرقية من React وFlutter.
2. إزالة التكرار بالمقارنة النصية ثم المراجعة البشرية، لأن التشابه النصي وحده لا يكفي.
3. مطابقة كل حديث مع الكتاب والرقم والراوي والحكم.
4. فصل الدعاء العام عن الحديث وعدم نسبته إلى السنة.
5. مراجعة نصوص الرقية آيةً وحديثًا، وإزالة أي عبارة غير موثقة أو وسمها بوضوح.
6. مطابقة كل تسجيل صوتي مع النص، والتحقق من ترخيصه.
7. تحويل البيانات المعتمدة إلى JSON/Dart لنسخة Flutter، مع نسخة schema مشتركة.
8. إضافة اختبارات تمنع إدخال عنصر بلا مصدر أو رابط مراجعة.

## الميزات التي تحتاج تكاملًا أصليًا أو مصدرًا خارجيًا

- البوصلة الحقيقية تحتاج مستشعرات الجهاز واختبارًا على iPhone وAndroid.
- مكتبة الأحاديث الكبيرة تحتاج مصدر بيانات وترخيصًا أو سياسة استخدام واضحة.
- صوت الأحاديث والأذكار يحتاج تسجيلات مرخصة ومطابقة للنص.
- منصة إحسان يجب أن تستخدم الرابط الرسمي أو API رسميًا، ولا تُنشئ حالات تبرع داخل التطبيق.
- التفسير يحتاج ملفات مصدر موثوقة أو تكاملًا رسميًا، ولا يكفي استدعاء نموذج لغوي.

## معايير قبول المحتوى

لا تُعتبر الميزة الدينية مكتملة حتى:

- يظهر مصدر كل نص.
- تُميّز درجة الحديث عند الحاجة.
- لا توجد نصوص مولدة أو منسوبة بلا تحقق.
- لا توجد عناصر مكررة غير مقصودة.
- يطابق الصوت النص الظاهر.
- تعمل حالة عدم توفر المصدر بوضوح.
- يمر المحتوى بمراجعة بشرية متخصصة قبل النشر.
